# @evansdai/trellis-pi-ext

Repository-owned Pi extension for the Trellis workflow, forked from the Pi
extension template generated by `@mindfoldhq/trellis`. The fork keeps the
Trellis integration that is independent of child-agent dispatch:

- task-context, startup, and workflow-state injection;
- primary-prompt suppression for `pi-subagents` child sessions; and
- lifecycle-bus tracking for gotgenes child sessions.

It deliberately does **not** register or implement the native
`trellis_subagent` dispatcher. Native progress cards, the `alt+o` shortcut,
native child-run/result handling, native Trellis Fleet production, frontmatter
compatibility, and native agent discovery were removed with that dispatcher.

## Dispatch ownership

On Pi and Oh My Pi, `@evansdai/pi-subagents` is the only supported delegated
run path. Its gotgenes-compatible `subagent` tools own permissions, progress,
results, and Fleet records. Use the global role definitions in the parent
configuration:

| Job | Role |
|---|---|
| Bounded implementation | `worker` |
| Independent read-only sanity/quality review | `oracle` |
| Deeper or external research | `researcher` |
| Fast local codebase reconnaissance | `scout` |

The role files are authoritative for model, thinking level, tools, context
inheritance, and turn limits. `oracle` and `scout` are read-only. The Trellis
extension injects the active task context for all supported child sessions;
it does not choose a child model or run the child.

Native Trellis role guidance remains available only for platforms that do not
use the Pi/Oh My Pi gotgenes path. Historical Fleet records with
`source: trellis` are data and are not migrated or deleted.

## Generated-extension conflict

The fork is normally loaded from global Pi settings. Pi also auto-discovers a
generated `.pi/extensions/trellis/index.ts` in the current project. If that
file is present, this fork yields and registers nothing so the two extensions
cannot register competing behavior. To use this fork in that project, move the
generated file out of the auto-discovered path (use the repository's recoverable
`trash` workflow where applicable) and keep the fork pinned globally.

This repository has no generated Trellis extension file; the fork is its only
Trellis extension provider here.

## Install

```bash
pi install git:github.com/evansdai/trellis-pi-ext@<immutable-sha>
```

Install only immutable Git refs. The parent configuration pins the exact commit
used by this environment. Removing the package is the rollback path; restore
the generated extension only if deliberately returning to native Trellis
dispatch on a non-Pi/OMP setup.

## Development

```bash
npm install        # development tooling only
npm run check      # typecheck + tests
```

The tests cover the retained lifecycle/context wiring, child-session guards,
and the registration/yield boundary that ensures native dispatch is not
registered by this fork.
